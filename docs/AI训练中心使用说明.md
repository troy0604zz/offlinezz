# AI 训练中心使用说明

训练中心采用 RAG、Semantic Layer、Few-shot SQL 和持续评测，不修改 Qwen3.5 模型权重。

## 推荐操作顺序

1. 在“文档知识”上传业务制度、指标口径和数据字典。
2. 在“DDL / Schema”录入数据库 DDL、方言和业务说明。
3. 在“指标”配置计算表达式，审核后发布。
4. 在“表关系”配置 Join 条件和一对多/多对一基数。
5. 在“同义词”配置业务口语到指标、维度或过滤条件的映射。
6. 在“标准 SQL”录入“问题 + 正确 SQL”，先保存为草稿，审核后发布。
7. 在“黄金评测”保存问题及期望 SQL/JSON，执行评测并观察得分。
8. 用户在数据问答中点击“需要修正”，提交正确 SQL；管理员在“用户反馈”中将其转为草稿案例，审核发布后形成闭环。

## Mock 与真实模式的区别

Mock 模式会对管理员已发布的标准问题做中文二元词相似匹配，相似度达到阈值时直接使用标准 SQL，因此无需 Ollama 也能演示训练效果。文档索引存放在内存中，但应用启动时会从已发布文档文件恢复。

真实模式会调用 BGE-M3 生成向量并写入 Qdrant。提问时检索文档片段，同时读取指标、关系和相似标准 SQL，拼装为受控上下文后交给 Qwen3.5。所有生成 SQL 仍必须经过只读、白名单、危险函数、超时和最大行数校验。

## 发布纪律

- DDL、指标、关系和 SQL 应由对应数据 Owner 审核。
- 退款、库存、客户数等容易发生多表放大的指标必须准备黄金问题。
- 不要直接发布用户提交的修正 SQL；先转成草稿，核对权限、口径和执行计划。
- 修改 Embedding 模型或向量维度时必须新建 Qdrant 集合并重建索引。
