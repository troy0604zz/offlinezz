# AI 训练中心使用说明

训练中心采用 RAG、Semantic Layer、Few-shot SQL 和持续评测，不修改 Qwen3.5 模型权重。

## 推荐操作顺序

1. 在“数据域与数据源”创建数据域，配置该域唯一的只读 Oracle 数据源并测试连接，再分配域内成员权限。
2. 切换到目标数据域，在“文档知识”上传业务制度、指标口径和数据字典。
3. 在“DDL / Schema”录入完整数据库 DDL、方言和业务说明；DDL 中出现的表会形成当前域 SQL 白名单。
4. 在“指标”配置计算表达式，审核后发布。
5. 在“表关系”配置 Join 条件和一对多/多对一基数。
6. 在“同义词”配置业务口语到指标、维度或过滤条件的映射。
7. 在“标准 SQL”录入“问题 + 正确 SQL”，先保存为草稿，审核后发布。
8. 在“黄金评测”保存问题及期望 SQL/JSON，执行评测并观察得分。
9. 用户在数据问答中点击“需要修正”，提交正确 SQL；管理员在当前域“用户反馈”中将其转为草稿案例，审核发布后形成闭环。

除原始用户反馈/审计记录外，文档、Schema、指标、关系、同义词、标准 SQL 和黄金问题均支持编辑与删除。编辑、发布或删除文档、Schema、指标和标准 SQL 时，系统会同步重建当前域的检索投影。

## Oracle 权威库与 Qdrant 检索投影

Oracle 是所有训练资产的唯一权威数据源。Qdrant 只保存可重建的语义检索投影：

- `DOCUMENT`：已发布文档的文本切片。
- `SCHEMA`：已发布 DDL / Schema。
- `METRIC`：已发布指标的名称、编码、业务说明和基础表；指标 SQL 表达式不写入向量库。
- `SQL_EXAMPLE`：已发布标准问题及说明；完整标准 SQL 不写入向量库，命中后按 `assetId` 回 Oracle 读取当前发布版本。

每个向量都携带 `domain / assetType / assetId / assetVersion / status / embeddingProvider / embeddingModel`。数据源凭据、权限、Join 关系、指标公式、完整 SQL、黄金结果、反馈、查询历史和报告不得写入 Qdrant。

## Mock 与真实模式的区别

Mock 模式会对管理员已发布的标准问题做中文二元词相似匹配，相似度达到阈值时直接使用标准 SQL，因此无需 Ollama 也能演示训练效果。文档索引存放在内存中，但应用启动时会从已发布文档文件恢复。

真实模式会调用 BGE-M3 生成向量并写入 Qdrant。提问时同时检索文档、DDL、指标说明和标准问题，再从 Oracle 读取当前已发布的指标公式、关系和完整标准 SQL，拼装为受控上下文。所有生成 SQL 仍必须经过只读、白名单、危险函数、超时和最大行数校验。

## 发布纪律

- DDL、指标、关系和 SQL 应由对应数据 Owner 审核。
- 退款、库存、客户数等容易发生多表放大的指标必须准备黄金问题。
- 不要直接发布用户提交的修正 SQL；先转成草稿，核对权限、口径和执行计划。
- 修改 Embedding 模型或向量维度时，系统强制重建所有活动数据域的索引；重建失败会撤销模型切换。
