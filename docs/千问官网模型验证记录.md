# 千问官网模型验证记录

验证日期：2026-08-09

## 验证环境

- 数据库：Oracle Database 19c
- 向量数据库：Qdrant
- 本地聊天模型：Ollama `qwen3.5:9b-q4_K_M`
- 本地向量模型：Ollama `bge-m3:latest`
- 官网聊天模型：`qwen3.8-max`
- 官网向量模型：`qwen3.7-text-embedding`，1024 维

API Key 仅从 `runtime/qwen-api-secret.ps1` 注入进程，未写入源码、发布包、日志或前端响应。

## 全链路结果

测试问题：

> 查询2026年不同客户等级的平均订单净销售额和订单数量，只统计已完成订单，按平均净销售额降序

| 方案 | 结果 | 后端耗时 | 返回结果 |
|---|---|---:|---:|
| 官网聊天 + Ollama/BGE-M3 向量 | 成功 | 5,454 ms | 2 行 |
| 官网聊天 + 官网向量 | 成功 | 6,346 ms | 2 行 |
| Ollama 本地聊天 + 本地向量 | 失败 | 多次复现约 7.7–28.0 秒 | Oracle `ORA-00934` |

官网模型生成的 SQL 通过 SQL 安全校验并在 Oracle 19c 成功执行。一次成功结果中，A 级客户平均订单净销售额为 `816666.6666666666666666666667`，订单数为 `3`。

本地模型在相同问题上生成了 Oracle 不允许的聚合表达式，执行阶段返回：`ORA-00934: 此处不允许使用分组函数`。这说明此前“未命中标准 SQL 时临时 SQL 容易失败”的主要原因之一确实是本地模型生成质量，而不只是训练数据数量。

## 官网向量验证

- 切换并重建已发布知识索引：2,007 ms
- 独立 Qdrant 集合：`aibi_qwen-api_qwen3_7-text-embedding_sales`
- 向量维度：1024
- 索引点数：8
- “净销售额”检索 TopK=3：返回 3 条

不同向量提供方使用独立集合，原有 `aibi_sales` 中的 BGE-M3 数据保持不变。

## 结论

当前测试数据下，官网 `qwen3.8-max` 的复杂 Oracle SQL 成功率和响应耗时均明显优于本机 9B 量化模型。该结果是单机功能验证，不是正式性能基准；正式评估应使用黄金问题集分别运行多轮，统计执行成功率、结果一致率、P50/P95 耗时和 API 成本。
