# 配置说明

系统通过环境变量配置，密钥不写入 Git。默认 Profile 为 mock：H2 + Mock AI + 内存检索。real Profile 使用 Oracle 19c + Qdrant，并支持在 Ollama 本地模型和千问官方 API 之间切换。

登录会话默认有效 12 小时，可通过 `AUTH_SESSION_HOURS` 调整。会话令牌仅以 SHA-256 摘要保存在数据库，用户密码使用 BCrypt 保存。生产环境不得继续使用迁移脚本中的本机验收密码；应修改账号密码、删除验收账号，或接入企业 SSO/LDAP。

Oracle JDBC URL 推荐使用 Service Name 格式：`jdbc:oracle:thin:@//数据库主机:1521/服务名`。本机实例为 `jdbc:oracle:thin:@//127.0.0.1:1521/AIBIPDB1`。若内网使用 SID，则改为 `jdbc:oracle:thin:@数据库主机:1521:SID`。应用会从 `classpath:db/oracle-migration` 执行 Oracle 专用 Flyway 脚本。

首次验证必须使用独立、空的 AIBI 平台 Schema，因为迁移包会建立平台表和演示销售表。若 DBA 已经审核并手工执行迁移，设置 `FLYWAY_ENABLED=false`；不要把自动迁移直接指向已有业务 Schema。平台库由 `DB_URL` 配置；AI Trainer 在“数据域与数据源”中为每个域绑定一个独立业务查询数据源。业务数据源账号必须是只读账号，禁止授予 DDL/DML 权限。

独立数据源密码使用 AES-256-GCM 加密后写入平台库。保存密码前必须设置至少 16 位的 `DATASOURCE_ENCRYPTION_KEY`；生产环境应使用随机高强度值，并通过主机密钥管理或 Secret 管理工具下发。迁移环境必须同步该密钥，否则历史密码无法解密。接口和页面只返回“是否已配置”，不会回显密码。

关键要求：BGE-M3 向量维度默认为 1024；如果更换 Embedding 模型，必须同步修改 `QDRANT_VECTOR_SIZE` 并新建集合，不能将不同维度或不同模型的向量混入同一集合。Qdrant 对外暴露时必须配置 API Key、TLS 或置于反向代理之后；本模板只监听本机回环地址。

Qwen3.5 的实际 Ollama 模型标签以迁移时 `ollama list` 为准。如果本地标签带参数规模或量化后缀，把 `OLLAMA_CHAT_MODEL` 设置成完整标签。

## Ollama / 千问官方 API 双提供方

聊天模型与向量模型可以独立选择：

- `AI_CHAT_PROVIDER=ollama|qwen-api`
- `AI_EMBEDDING_PROVIDER=ollama|qwen-api`
- `QWEN_API_CHAT_MODEL=qwen3.8-max`
- `QWEN_API_EMBEDDING_MODEL=qwen3.7-text-embedding`
- `QWEN_API_EMBEDDING_DIMENSIONS=1024`
- 使用千问官网时，`QWEN_API_BASE_URL` 必须与阿里云百炼控制台中 API Key 所属地域和业务空间显示的 API Host 一致。无外网部署也可将该 OpenAI-compatible 兼容层指向内网模型网关；此时变量名仍沿用 `QWEN_API_*`，但地址、Token、聊天模型 ID 和 Embedding 模型 ID 均填写内网网关值。
- `DASHSCOPE_API_KEY` 只能配置在服务器环境变量或被 Git 忽略的 `runtime/local-real.config.ps1` 中。

本机配置方法：复制 `deploy/qwen-api-secret.ps1.example` 为 `runtime/qwen-api-secret.ps1`，只在这个本机文件中填写轮换后的新 API Key 和控制台显示的 API Host。启动脚本会在主配置之后加载它。`runtime` 目录已被忽略，不会进入发布包或 Git。重启应用后，使用管理员账号进入“AI 训练中心 → 模型配置”切换。

聊天提供方切换立即生效。向量提供方或模型变更时，系统强制重建所有活动数据域的 Qdrant 检索投影，不允许跳过；重建失败会撤销运行时切换。重建成功后，当前 `QDRANT_COLLECTION_PREFIX` 下该数据域的其他 Embedding 集合会被清理，避免已删除或已停用资产在切换后重新出现。页面切换属于当前进程的运行时设置，服务重启后重新采用环境变量中的默认提供方。

## Qdrant 与 Oracle 同步清理接口

系统统一使用 `QDRANT_COLLECTION_PREFIX=aibi`，集合名以 `aibi_` 开头。Oracle 是训练资产的权威数据源，Qdrant 只保存可重建的检索投影。清理接口因此会同步删除 Oracle 资产和 Qdrant 投影，不能当作单纯的向量缓存清理接口使用。

可清理的向量类型与 Oracle 表对应关系：

| `assetType` | Oracle 权威表 | 说明 |
| --- | --- | --- |
| `DOCUMENT` | `knowledge_document` | 同时在事务提交后删除原始文档文件 |
| `SCHEMA` | `schema_asset` | DDL / Schema 训练资产 |
| `METRIC` | `semantic_metric` | 指标定义 |
| `SQL_EXAMPLE` | `sql_example` | 标准问题和标准 SQL；Qdrant 本身不保存完整 SQL |
| `ALL` 或不传 | 上述四张表 | 不删除关系、同义词和黄金问题，因为它们没有 Qdrant 投影 |

先预览 Oracle 中将匹配的资产数量：

```http
GET /api/v1/admin/vector-data/purge-preview?domain=sales&assetType=DOCUMENT
Authorization: Bearer <AI_TRAINING 用户令牌>
```

执行清理：

```http
POST /api/v1/admin/vector-data/purge
Authorization: Bearer <AI_TRAINING 用户令牌>
Content-Type: application/json

{
  "domain": "sales",
  "assetType": "DOCUMENT",
  "confirmation": "DELETE_QDRANT_AND_ORACLE"
}
```

- `domain` 与 `assetType` 可以组合使用。
- 不传 `domain` 表示跨所有数据域，只有 `AI_ADMIN` 角色可以执行。
- 不传 `assetType` 或传 `ALL` 表示四种向量资产全部清理。
- 每次成功清理都会写入 `audit_event`，事件类型为 `VECTOR_DATA_PURGED`。
- Qdrant 不支持与 Oracle 组成真正的分布式事务。实现采用 Oracle 事务、失败回滚和 Qdrant 投影补偿重建来降低不一致风险；异常后仍应根据返回的错误码检查 Qdrant 健康状态。

真正的无网内网环境不能直接调用千问官网；迁移后应将默认提供方恢复为 `ollama`，除非内网已有经审批的 API 网关或代理出口。
